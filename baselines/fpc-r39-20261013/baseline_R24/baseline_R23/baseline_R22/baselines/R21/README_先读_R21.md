# R21｜RAZR 60 Ultra 对标：双等尺寸纵向滑盖的双终点信号接点仓

**结论：研究级代理几何；整机制造和充电/电源安全放行 = 拒绝。**

本文件夹是 R17 → R18（连续跨舱FPC碰撞）→ R19（双终点触点候选）→ R20（双狗齿接点仓未通过装配）之后的一次新的实体整合。**不是完成手机CAD、厂商零件CAD或寿命报告**。

## 用户形态约束（不可更改）

- 两个完整独立的同高同宽功能舱；每舱当前研究外形 94.25 × 73.99mm，并未恢复 RAZR 60 Ultra 原厂收纳尺寸。
- 收纳时位于后下层的B舱纵向上滑79.75mm，展开成为上半部，再向前就位8.2mm；A舱固定成为下半部。
- 只有一块约7英寸柔性OLED；**没有任何独立背部外屏**。B舱顶部单次U形折返，背部平面储屏；卷轴只卷张紧机构。
- A舱优先大电池，B舱为SoC、相机、小电池和储屏；4700mAh是未经实装的目标。

## 本次实际更新（代码＋实体检查）

1. 用 R17 带OLED与内部FPC真实通道的 `b_shell_local` 作为B舱基线，不再直接拿 R16/R19 早期实心功能舱冒充已解决OLED空间。
2. R20收纳端信号接点仓从局部Y=30mm移到Y=18.5mm，使其避开 R17 假设B电池Y=22..58mm包络。候选槽体切除侵入电池包络 **27.56715→0mm³**。A舱接收焊盘必须相应迁移，实际PCB改版未完成。
3. R20位于OLED有效区域下方的两条固定导向肋不再保留，因为它们会在上滑末端与OLED相交。改为B壳内部的移动狗齿/载体槽，并在可用空间内留名义0.15mm的导向净距；无制造工艺或滑动寿命验证。
4. 展开端托岛加入侧向导槽、载体背梁支撑和0.8mm局部补强；托岛接点支撑底板名义0.90mm，假设再损失0.15mm时为0.75mm（仅局部厚度筛查，不是FEA）。
5. 保留 R17 原OLED和本舱FPC长度守恒运动学。五个关键姿态中，重建B壳同A核心、A桥片、OLED及本舱FPC的**指定CAD正体积交集为0**；B框为一个有效连通实体。完整Y/Z全程的公差扫掠、真实外屏封装、装配服务通道均未完成。
6. 7套 STEP 每态24个已重导入的**代理实体**，3个DXF名义YZ剖面和离线运动HTML。另有2份明确标为“强制伸出、未验证安全”的反例STEP。

## 不可忽略的R21失败

- 活动B舱到OLED**仅有效区宽度**假设下最近距约0.319619mm。如果真实OLED封装每侧额外0.15mm，该距约0.28954mm；每侧额外0.20mm则约0.23954mm，均达不到本项目自行设定0.30mm保护目标。供应商实际边缘尺寸尚未知。
- OLED的R3.4mm动态弯曲假设没有厂家许可，蠕变、展平力、接触张力和循环寿命未实测。
- TE Connectivity 2199001-1官方标明Signal用途、未压高度1.2mm、工作高度0.7-1.0mm、最大1.5A。它不构成4700mAh双电池主电流母线或USB-C的大电流认证。供应商STEP公开入口可查询但本次未成功取回，模型仍为标记清晰的矩形代理。
- R20的共因故障：左右挡块**均被错误解锁**，伸缩接点在无端面坐实证明下仍能自由伸出；R21解决的是空间布局，不假装修复安全互锁。
- R20假设温度/磨损叠加后信号触点工作高度达到0.69–1.01mm，越过官方0.70–1.00mm工作范围；R21未修复该公差链。
- 没有实物：电池、主板、相机、真实OLED、触点弹簧、狗齿传动、跨舱主电源、完整静态/动态FPC的厂商CAD。**没有真实接触压力、老化、扭转、跌落、耐尘、热或30万次循环数据。**

## 复现

依赖 Python 3.13、CadQuery/OCP、Shapely、SciPy、Matplotlib、ReportLab、ezdxf。`baselines/R20`包含 R20/R19/R17 的最小自足源码（包括相关R16源），不依赖原路径或联网。

```bash
bash run_checks.sh
```

完整复算会先重做R21几何与负向数据，输出七份STEP并重新导入检查，再运行本轮和R17/R19/R20单元测试，绘制工程图及五页PDF。程序测试通过**包括正确拒绝不合格状态**，不代表手机验收通过。

- `r21_geom.py` — B壳槽体、收纳/展开仓、移动零件包络和五态实体相交。
- `r21_verify.py` — OLED有效区加宽对照、电池占用、二维长度守恒与共因故障记录。
- `r21_export.py` — 七态STEP、三态DXF和离线HTML。
- `r21_report.py` — 同源PNG/SVG与PDF。
- `test_r21.py` — 28项自检（失败门槛明确保持失败）。
- `verification/R21_results.json`、`R21_screen_edge_sensitivity.csv`、`R21_step_manifest.json`、`R21_SHA256_MANIFEST.json` — 证据文件。
