# Inherited locked-wheel byte identity supplement

This read-only execution completed all **21 inherited system-site packages** in the canonical 43-package environment. The other 22 packages are identified by the saved overlay requirements and are outside this supplement. The repository remained at frozen candidate **bec1c8d79a37b4ba387d606cd7ea1c5867f3f9eb**; the lock hash remained **b1387fbbfa74e39474818a8a6235ba7ddf1d97d00629babb1d0e53971141fe6a**.

## Actual result

- Exactly 21 platform-compatible wheels were downloaded from the public URLs recorded in the original `uv.lock`; all archive sizes and SHA-256 values matched the lock. Downloads total **177,647,499 bytes (169.417857 MiB)**.
- **1,650 original payload files**, totaling **691,908,944 bytes**, matched the installed files byte for byte. No original wheel member was unmapped or missing, and no original payload differed.
- **86 original distribution metadata files** also matched. The 21 installed `RECORD` files differ because installation rewrites them; those comparisons are retained and excluded from original payload equivalence.
- Files were compared by streaming both originals and installed bytes, then the mapped installed files were hashed again to confirm they had not changed during the comparison. No CAD/VTK package was imported, no installer ran, and no repository or environment file was written by this execution.

## Limits retained explicitly

The result establishes equality of the **current installed original wheel-owned files** to the selected lock-pinned wheels. It does not prove which wheel an installer historically used, the installer event chain, already loaded process memory, generated bytecode, generated console scripts, or files not recorded by these distributions. The selected compatible wheel is not claimed to be the historically chosen wheel.

There are **991 installed RECORD extras**, all observed to exist and independently listed with their current SHA-256 in `excluded-generated-files.json`:

| Excluded category | Count | What is established |
| --- | ---: | --- |
| Generated `__pycache__` bytecode | 952 | Existence and current SHA only; not compiled, executed, or established equivalent to source |
| Installer-added metadata | 38 | 21 `INSTALLER` and 17 `REQUESTED` entries; labels are not installer provenance |
| Generated `ezdxf` console script | 1 | Text calls `ezdxf.__main__:main`, agreeing with the wheel entry-point declaration; script bytes are absent from the wheel and remain outside equivalence |

No blanket claim that the entire runtime or all executed code has been proven is made. No historical installation evidence has been synthesized.

## Method and independent receipt check

`compare_locked_wheels.py` is the exact executed audit script. Its source SHA is recorded in `summary.json`. It streams the 21 wheel downloads into an isolated task tmpfs, validates archive size/SHA, checks wheel members against their original RECORD, maps wheel files to the installed base prefix, compares bytes and hashes, and records unmapped files and generated extras separately. Original wheel bytes were not installed or extracted into an environment.

The original execution script returns zero when all 21 packages complete; that exit code alone does **not** reject every file mismatch. Its consumers must inspect the structured result. The supplementary `check_receipt.py` performs that explicit gate: it checks all 21 exact name/version/URL/SHA/size tuples against the saved original lock, all per-file equality/size/hash results, nonempty payload counts, completeness, and scope flags. The actual receipt passed. Five negative checks rejected an unlisted locked tuple, an unmapped original, a payload mismatch, an inconsistent per-file SHA, and an incomplete execution.

Independent read-only review by `/root/validation_audit` also parsed the original lock and confirmed all 21 selected tuples, the payload/metadata totals, zero unmapped members or symlinks, and the excluded categories. The executed comparator itself is preserved unchanged.
