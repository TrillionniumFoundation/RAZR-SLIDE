## G4 powered motion contract

The fixed phase program is: locked baseline; unlock left and right; slide out;
seat; install left hold, right hold and support; hands-off open; remove support,
right hold and left hold; unseat; slide in; relock right and left; locked final.
This retains the current manual accessories and both directions of operation.
It does not imply an automatic hinge or stowable support.

Both original-battery and original-charging modes must cover all 17 phases. The
nine function groups are power, pack A, pack B, USB, display, touch, camera, RF,
and audio/sensors. Fourteen mandatory metric types cover rail voltage/current,
resets, both pack currents and temperatures, USB errors/disconnections, display,
touch position, camera, RF and audio/sensor errors. A plan may add several named
rails under one metric type; each channel needs its actual measured location and
identity evidence.

Acceptance limits, the cycle count, sample count, maximum sampling gap and
alignment error require original source references and locators. The templates
leave those values null. The evaluator checks calibration evidence, uncertainty
intervals, original function observations, the full phase/mode/cycle inventory,
and raw sample timestamps. The sampling-gap calculation spans phase and cycle
boundaries within each specimen and power mode; an unobserved interval cannot
be divided into several individually small edge gaps.

An absent observation, missing source or uncertainty interval crossing a limit
remains `unknown`. A definite numeric violation or an explicit observed function
failure remains `fail` even if other phases are missing. Complete synthetic
fixtures remain `unknown` and cannot provide a physical prerequisite.

## G5 endurance and process contract

The life target, specimen count, checkpoint schedule, exposure ranges, sample
gap, alignment allowance and critical dimensions all require a declared source.
There is no invented default cycle life, force, retention, thermal, humidity or
load limit. The plan retains the full manual phase program and requires eight
checkpoint metric types: operating force, unlock force, left/right skew, relock
error, retention drift, FPC resistance, display errors and USB errors.

The cycle CSV is a checked summary. Qualification also requires hash-bound raw
exposure samples, hash-bound original phase windows, phase-observation evidence
and synchronization evidence. The evaluator independently recomputes phase
coverage, temperature/humidity/speed/load extrema, cycle count, chronology and
maximum sampling gaps. Gaps include actual adjacent samples across phases and
cycles. Every supplied CSV statistic must agree with the rederived value. A CSV
without its raw records is explicitly `summary_only_not_qualifying` and cannot
pass. A summary hiding a raw peak or underreporting a sampling gap is rejected.

Each specimen must complete consecutive original cycles and the declared final
checkpoint. All checkpoint/metric and specimen/critical-dimension cells must be
present. Uncertainty that straddles a sourced limit remains unknown. Observed
failures and their references are retained, including early termination.
Replacement or maintenance does not silently continue an uninterrupted life
claim. Exposure deviations are labelled as protocol-condition findings.

## Identity, prerequisites and trust boundary

G4 requires physical, current-EP5 G3 evidence for the same specimen. G5 requires
that G3 evidence and physical G4 evidence with verified commit bytes. Plan,
acquisition and as-built records must agree on candidate identity and specimens.
The design binding includes all current top-level integration Python sources,
the declared EP5 source dependencies and native payload roles, in addition to
the three design configurations. In physical mode, actual file bytes must match
the declared Git commit. A record bound to another commit may be inspected, but
does not qualify the current `HEAD`, even if the design JSON files are unchanged.

The independent preregistration attestation binds the semantic hashes of the
exact plan and acquisition, specimen inventory, registration chronology and
original evidence. The program verifies the attachment bytes, chronology and
consistency; it does not authenticate a person's identity or independently
prove that an attachment depicts the claimed physical test. This limitation is
included in every result. All release flags remain false even for a complete
sampled-protocol decision.

Generate plans in the checkout of the candidate that will be tested. A later
commit, including an evidence-only commit, is a different `HEAD` for the strict
current-candidate check. Historical plans should be evaluated in their declared
candidate checkout or regenerated and reapproved for the new candidate; changing
only a plan's commit label is not sufficient.

## Reproduction

Use the repository's locked environment. Output paths must be new directories
or files so an earlier result is not overwritten.

```sh
.venv/bin/python -B integration/product_ep5_ecad.py --output /tmp/ep5-new-artwork
.venv/bin/python -B engineering/engineering-integration-20261025/product/build_product_delivery.py --output /tmp/product-new-plans
.venv/bin/python -B -m unittest tests.test_ep5_fpc_ecad tests.test_product_qualification_contracts tests.test_g3_current_candidate -v
.venv/bin/python -B -m unittest discover -s integration/product-study-tests -p test_qualification_contract.py -v
```

For an actual acquisition, its original evidence references resolve relative to
the acquisition JSON's directory:

```sh
.venv/bin/python -B integration/product_qualification.py --plan /path/G4-plan.json --acquisition /path/G4-acquisition.json --review /path/G4-review.json --output /path/new-G4-decision.json
```

The same command handles a G5 plan. Malformed evidence raises an error; otherwise
read the decision's `status` and `blockers`. A successful program exit alone is
not a qualification pass. The test fixtures are explicitly synthetic and their
small numbers are not approved product criteria.

`validation-r1` preserves the first 61-test execution and original G3 57-test
execution. `validation-r2` records the subsequent 64-test execution after the
cross-phase/cross-cycle sampling-gap correction. Neither receipt represents a
physical test or a native KiCad result.
