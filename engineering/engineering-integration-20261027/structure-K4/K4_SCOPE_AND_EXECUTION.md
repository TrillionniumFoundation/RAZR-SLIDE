# K4：当前完整实体的 12 个局部窗口原生检查

## 交付范围

K4 直接读入已完成 K3FULL `stow_tabs_3` 的完整 `A_BACK_PANEL`、`L_KEY`、`R_KEY` STEP 原件。它只检验冻结的 12 个局部窗口：每侧 KEY 的 yoke、两根新增桥腿、前横梁，以及 panel 的低端止挡和高端 toe。两个加宽参考负对照应产生正缺料。每个窗口使用完整实体与窗口的 Common，然后做实际局部材料和冻结参考盒的两个有向差集。有效空 Common 是可计算的局部材料不符；非法拓扑或计算异常保留为未决。只有原 `whole_material` 已验证为 0 solid、体积恰为 0 的有效空材料，才按 `A\B` 集合恒等式返回原左操作数；身份和未调用 native Boolean 的事实单独记入日志。未知 null/ValueError 不得当作空集合。原 `1e-7 mm³`、拓扑与正有向体积判据不变。

独立读回在另一个已验证的 owned 子进程中重新读入三个原 STEP，导入生产进程保存的每一个 BREP 和非空 STEP，对每个 STEP/BREP 做完整材料的双向差集，再从完整原件重做窗口和负对照。生产者的 pass 字段不能代替这些计算。两个进程使用同一个锁定内核；没有第二内核声明。

这不是全件最薄壁算法。特别是局部 `.38 × .36 mm` 截面、精确序列化面距或 12 个窗口匹配，都不证明完整 KEY/panel 的全局最薄壁、材料强度、制造余量、全部功能接触面或完整 15 维允许域。当前 FE、真实材料/公差、同 specimen OEM 互连和 G3–G5 仍按现有缺项保留，任何 go 标志不改。

## 容量和执行顺序

生产者最多 38 次布尔运算（若有已验证空集合恒等式，则相应减少真实调用并保留完整任务日志）；读者最多 190 次，包括 62 个局部/保存材料重算与最多 128 个 STEP/BREP 双向差集。每个进程重新导入三个完整原 STEP，生产者最多保存 64 个 BREP 与 64 个非空 STEP；没有重新执行完整 factory 或全体对。

已有 K3FULL stow3 的实际完整 factory 为 253.317231384 s、采样 peak RSS 574,365,696 B；读者为 194.26243259199998 s、563,609,600 B。这些是较大的旧工况，不能当成 K4 的实测性能。K4 预估每进程 60–300 s；硬门仍是每进程 1,200 s、RSS 1,536 MiB、共享估算不可回收内存 6.8 GiB、启动附加内存 2,048 MiB、启动普通盘 256 MiB、运行普通盘 100 MiB。

另加严格输出限制：每个子进程 RLIMIT_FSIZE 16 MiB；每次写形状前保留一个完整允许文件空间；科学目录最多 128 MiB、总进程输出最多 160 MiB；工程 export 最多 384 MiB。下载前另需 2 GiB 普通可用空间。这些附加限制不能取消原资源门。单 job、最大并行 1，生产者后才启动读者；原 3,240 s 外部 deadline 和 3,600 s job 上限保留。

顺序为：不可变 S4 源字节核验 → 原 INT/TERM owned 清理控制 → 原 43 包锁定安装/环境检查 → 原 ZIP 全字节读取 → owned 生产者 → 实际另进程读者 → 结构化结果分类 → 原源/环境后验 → 工程 allowlist 导出。对生成的实际 YAML heredoc 和 Python `-c` 内容做语法检查，避免只检查旁边的源文件。

## 失败与资格语义

`K4-complete-observation.json` 分开列明：已计算出的局部材料不符、未决求值/保存/资源失败，以及生产者与读者不一致。只有全部 12 窗、2 负对照、全部序列化读回、源/环境/owned 生命周期及工程保存均满足，才可报告本项局部检查 pass。工作流绿灯也不能给全局结构或允许域资格。

生产者失败后，只要实际 report/controller 存在仍尝试独立读回；无法验证原 owned 身份或缺少原件时，读者明确失败，不补造数据。所有可取得的科学形状、原报告和 operation journal 都按原字节保存，允许失败、未决和部分进度进入工程包。raw `/proc`、环境、PID 身份和异常私有路径只留在临时 runner；公开仅类别、SHA/字节、有限数值资源与局部验证投影，不声称原 runtime 永久保存。发布和后续归档由根代理完成。
