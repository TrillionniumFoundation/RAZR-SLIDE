# K2: finite full-factory endpoint checks after actual K1 clearance

This prepared diagnostic requires both actual K1 factory and independent-reader
reports to be complete and clear. It cannot run from a prepared plan or from
successful workflow step labels alone. Any real K1 failure prevents this stage.

Four explicitly finite states are planned: STOW with both TAB controls at zero,
STOW with both at 3 mm, PREDOCK at full slide before seating, and fully seated
OPEN with the original seven installed accessories. The first three use 154
participants and 11,781 pairs; OPEN uses 161 participants and 12,880 pairs.
Each point has a complete actual factory and a separate whole-STEP/all-pair
reader. Across four points this schedules 96,446 fresh pair calculations.

The material adapter imports the actual independently verified K1 q=0 KEYs.
Before any replacement, each new S4 factory's original KEY is returned to q=0
and compared in both material-difference directions to the frozen original KEY.
Only the two whole KEYs are replaced. Actual full-factory FPC, OLED, SPRING,
STOP, control and accessory geometry is constructed at every endpoint; their
motion is not approximated as generic rigid translation.

This does not cover independent TAB/flank ranges, KEY/crosshead offsets,
telescope allocation, intermediate slide/seating, reverse motion or actual
out-of-profile end states. The unmodified S4 factory keeps rejecting unsupported
q; that rejection is not a physical stop certificate. Loads, preload, material,
process, wall tolerances and strength remain unqualified. All physical and
manufacturing go flags stay false.

The owned supervisor preserves the existing 1200 s / 1536 MiB finite worker
budget, 6.8 GiB shared unreclaimable limit and original disk/startup guards.
F1a measured approximately 487–491 s per factory and 364–370 s per all-STEP
reader; the remaining allowance must accommodate frozen-material input checks.
Actual K1 timing will be included when the executable binding is frozen.

Only reviewed source and engineering models, complete pair journals and marked
report projections are exported. Both K1 prerequisites are copied only through
their exact manifest allowlists. Raw runtime remains ephemeral and is not
claimed to be durably preserved.
