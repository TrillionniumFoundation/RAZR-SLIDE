# EC1a：保留原 S4 检查的隔离运行环境诊断

EC1 首轮 `40273665517`（诊断提交 `4bd6be0cf9b6335ffe0195c0b658b0c7d9d9005d`）未进入 native readback 或 DRC。34 个固定软件包已逐项校验，五个 S4 源文件的前后 SHA256 相同。公开工程投影只保留了 `kicad-version.log` 的 SHA256，未保留该日志内容；job stdout 也没有该内容。因此当前证据尚不能确定具体缺失库、ABI 或其它失败原因。

首轮的失败是本次隔离运行环境的先决失败，不是 PCB DRC 发现了电气违规，也不改写已有 E3、原 S4 源字节绑定的 native 检查结果。首轮原件与新诊断分别保留。

## 最小变化

- `run_ec1.py`、`export_ec1.py`、`EC1_PINNED_PACKAGES.json` 与首轮逐字节相同。
- S4 commit 固定为 `dd7def6e6a4de9f47dc91ca2ab336fb1a8828560`，五个原检查/设计文件与原包 SHA256 完全保留。未修改任何原门槛、原命令或功能几何。
- 平台 apt 前置清单保持首轮不变；没有加入猜测的库，也没有根据错误自动安装包。
- 原验证器仍首先执行。原生步骤失败仍使 workflow 失败；后续诊断不会把失败改成成功。
- 原 exporter 完成后，新增 `diagnose_ec1.py`。它读取原 `version` 命令状态与日志，针对同一隔离环境运行 `/usr/bin/ldd`，目标仅为原 `kicad-cli` 与唯一的 `_pcbnew*.so`，再重试原 `kicad-cli version` 命令。每项新进程最多 15 秒，不运行新 DRC。

## 精确输出边界

新增 `isolated-linkage.engineering.json` 是派生工程投影，加入原工程导出 MANIFEST；原生产者记录不修改。仅输出固定类别枚举、退出码、有限计时、原始字节数与 SHA256、严格 SONAME、三段数字版本、已知 ABI 数字版本。命令数组只保留三个原标签及退出码/计时/log SHA，不输出 argv。

不输出原始 stdout/stderr、解析出的路径、环境变量、用户名、符号名或任意错误消息。未识别文本只记未知行数/未知状态，不以猜测补全。新私有诊断日志留在临时运行目录，不随 artifact 上传；没有声称它们已持久归档。超过 1 MiB 的单项输出不从截断前缀作判断。

原工程 exporter 的输出范围与首轮相同，仍包括明确标记的原 artwork 与工程投影；没有将 raw runtime 或包内容加入公开产物。

## 使用结果的规则

必须读取实际新投影，才能将原因分为缺少共享库、ABI 版本、符号、信号、未识别失败或正常版本执行。`ldd` 缺库名是该 runner、该隔离环境的直接观测；不能由旧机器的已安装库推出新 runner 具备相同依赖。只有实际观测支持后，才可以另提交明确依赖修复；该修复仍须保留原 34 包身份和原验证器。

本次本地检查只执行了六个纯解析/隐私负测试、Python 3.10 语法检查、shell 语法检查、工作流内嵌字节和原 S4 源 Git 对象 SHA 校验；未运行本地 KiCad。此准备记录不是 native ECAD 通过证据，也不提供 OEM 引脚、信号完整性、叠层、动态 FPC 或制造资格。
