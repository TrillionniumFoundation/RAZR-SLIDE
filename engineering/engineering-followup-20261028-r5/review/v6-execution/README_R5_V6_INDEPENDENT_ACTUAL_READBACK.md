本审计没有导入 producer、primitive helper 或 checker，没有重跑完整通道搜索、原 R4 包络、V5 producer 或 native CAD。

## 两次保留的审计器失败

V1 在0.494677217 s、319项检查后停止，尚未开始几何重建。它错误要求 `os.getpid` 等于宿主 `/proc` 所见PID。本地原 owned 链保存了例如 `[1490592, 5]` 的 NSpid 链；两种PID分别是同一进程在外层和内层namespace中的标识。V2改为严格核对链两端、内外父进程对应、namespace及starttime，保持原owned验证语义。V1源码、登记、完整失败报告未覆盖。

V2 在0.392978387 s、478项检查后停止，同样尚未开始几何。额外的“所有 `/proc` VmHWM 都必须不大于最终 entry/getrusage peak”假设被一条真实预检观测否定：42,881,024 B 对42,868,736 B，相差12,288 B。差异原因没有被建立。V3按原supervisor对每个观测分别不超过805,306,368 B的门和entry自身的同值门进行核对，并保留两值、较大值及差异。原科学输出、限值与来源均未改动，原两个门都通过。

这两次是审计器读取本地证据时添加的额外假设失败，不是原V6数学运行失败。它们仍作为真实失败记录保留；成功V3不会删除或重标早期记录。
