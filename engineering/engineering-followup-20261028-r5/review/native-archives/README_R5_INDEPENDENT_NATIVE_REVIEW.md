# R5 当前 K3 两中途归档的跨作者独立复核

独立程序没有导入或执行被审查的 `audit_recovered_k3_factory_r5_v2.py`，也没有导入 CAD 内核。它直接从两份实际 ZIP 重新读取原归档成员、完整矩阵、事件日志和已有 STEP 读回记录，再与 R5 审计输出逐项核对。

实际完成时间为 18.546938982995925 秒，峰值 RSS 为 209,514,496 字节；低于本只读审计预先登记的 300 秒／268,435,456 字节界限。这里没有宣称原 native 的启动磁盘／共享内存门通过，没有据此执行新 native 几何。

## 已实际核对

- 两份完整 ZIP 的固定字节数和 SHA256；每份 4,715 个 manifest 成员逐项流式读到 EOF，累计 882,885,558 个解压成员字节的 SHA／尺寸／CRC 一致。
- 36 份矩阵副本各自包含 154 个唯一参与体与完整 11,781 个无序体对；共 424,116 行体对、848,232 条 selected／completed journal 事件逐项匹配。
- 按历史原报告 SHA 去重后是 12 份原报告：F1、K1、当前 K3 各 4 份。原 F1 的 panel／KEY 正穿透完整保留，不能把嵌套副本算成多次新执行，也不能错当成当前 K3 的失败。
- 当前 K3 的近、远两姿态分别是 slide `23.142044210239405`／`60.880681403413135 mm`；对应两侧 KEY 的 q 是 `3.482188470506243`／`9.160729490168748 mm`。slide 与 KEY q 是不同坐标。
- 两姿态各有 154 件完整 BREP／STEP 字节对应，原单独 STEP reader 绑定同一 producer；各 11,781 个体对的 Common 差值最大为 0，两侧 panel／KEY 的直接 Common、strict Common 与矩阵值均为 0。
- 近姿态最大 STEP 体积读回差值 `1.2187229003757238e-9 mm³`，远姿态为 `5.857145879417658e-10 mm³`。最大边界坐标读回差值分别约 `9.408e-12` 和 `8.750e-12 mm`，均在原 `1e-7` 判据内。
- 当前 R3／R4 的整个 panel BREP 与左右 K1 q0 STEP，分别在归档找到精确字节相同的成员；K1／K3 命名源码、合同和绑定文件实际 SHA 一致。panel 账本仍是移除 `0`、增加约 `4.62456 mm³`。两侧 KEY q0 的原材料差集记录、12 个原独立早期几何检查与 R5 材料桥记录相符。
- 153 个非 panel 参与体的现存 inventory 中体积、边界和 solid_count 与当前导出签名一致。这个核对是**记录的签名一致性**，不是由有限签名重新证明任意两材料集合相等；整个材料对应结论还依赖归档的原比较和来源约束。

## 保留的边界

这是对**历史科学记录的当前独立字节与结构读回**。原 STEP reader 是单独进程、独立材料构造器，但没有使用另一种 CAD 内核。归档明确是 engineering projection，原 runtime identity 等字段被排除；不能从这些投影重建原 runtime 原报告或追认历史执行环境。

两中途有限姿态通过不能推出全连续域通过，不能闭合 FE、真实材料公差、保持／回锁机构或 G3–G5 实物试验。审计代码和报告保持这些资格标志为 false，原候选材料和原阈值均未修改。

## 资源说明修正

预登记计划用“每次一个受限 ZIP 成员”描述主输入读取，但实现为了逐项核对派生审计输出，曾同时保留一份完整派生矩阵集合（18 张表）。因此它并非严格只保留单张 JSON 的内存算法。实际峰值已如上记录，仍满足预登记的只读审计 RSS 上限；原计划不覆盖或改写，执行差异另记于 `R5_REVIEW_EXECUTION_NOTES.json`。这一说明不改变任何科学值或审计检查结果。
