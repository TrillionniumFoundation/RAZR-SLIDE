# Structural diagnostic scope

The input is the complete A_BACK_PANEL STEP produced by the fixed bearing-web candidate. No beam, hole, post, rail or control feature is deleted for meshing. The Gmsh import must have exactly one volume and match the native STEP volume. The linear geometric tetrahedral mesh approximates curved boundaries; this is not an exact-CAD displacement solution. Quadratic tetrahedral displacement interpolation is used, not a coarse linear-tet bending claim.

The optional tools are gmsh==4.15.2 and scikit-fem==12.0.2, installed in a separate analysis-only target directory with --no-deps. Existing locked CadQuery/NumPy/SciPy and project uv.lock are unchanged. Mesher/solver optional dependencies are not prerequisites or skipped cases in the canonical unit count.

Four independent load columns apply a unit resultant uniformly over each complete inner post face (left/right, front/rear). They are diagnostic load distributions, NOT measured cover-contact pressure and NOT equal load-sharing among posts. The response matrix retains interactions among these independent columns. Contact onset, sliding, separation, finite rotations, frame compliance, thread flanks and real preload are not solved.

E=1 N/mm2 is a normalization, not a proposed material. Poisson ratio=0.3 is an explicit synthetic assumption. For fixed Poisson ratio and these linear boundary conditions, if R=E*u/F in 1/mm, actual displacement would scale as u=R*F/E after actual material/load selection and confirmation of small strain. No actual allowable force, installation torque or material batch is inferred.

Two whole-panel boundary-condition studies were requested: (1) every displacement at the four actual FRAME mounting-head bearing rings is fixed; (2) the entire bottom skin, including all displacement nodes with Z<=0.65mm, is fixed. The latter is the artificial rigid-base comparison, not another physical assembly. The former still assumes infinitely stiff mounting constraints and neglects the rest of the real mechanism's stiffening/contact contributions. Neither is the certified frame-panel connection.

The mounting-ring boundary was solved at both mesh sizes with the same linear constitutive law, load faces and supports. The requested whole-panel rigid-skin boundary was NOT completed. Checks include finite positive element measures, complete volume, total force and moment equilibrium, residual on free DOFs, work/strain-energy equality, response reciprocity and positive response eigenvalues. Analytic uniaxial/rigid-motion benchmarks also run in P1 and P2 at several E/nu values. Agreement between two meshes is assessed against a declared 5% target for average loaded-face displacement, not an error bound for peak stress, contact, buckling or all solution quantities.

Preserved failures: two original whole-panel meshing attempts encounter the counterbore/sidewall tangent region; a ring-style addition creates unreliable/invalid native Booleans and is rejected; whole old/new panel differences return incompatible full volumes, so the accepted material certificate partitions both complete bodies into four disjoint local boxes plus the entire unchanged complement. An initial solver attempt completes one boundary but hits its 12GiB virtual-memory cap while retaining the first sparse factorization during allocation of the second. The revised solver releases each factorization and uses symmetric ordering without changing the elastic problem; the failed run is not a completed result.

Sources: https://gmsh.info/doc/texinfo/ ; https://scikit-fem.readthedocs.io/en/stable/ ; https://scikit-fem.readthedocs.io/en/latest/listofexamples.html#example-11-three-dimensional-linear-elasticity ; https://comet-fenics.readthedocs.io/en/latest/demo/elasticity/2D_elasticity.py.html

These sources support the meshing/linear-elastic formulation, not this product's material, boundary stiffness or service load. All hardware/manufacturing go flags remain false.

## Final execution correction and completed structural scope

The original COLAMD solve completed and saved its entire mounting-ring displacement/force/reaction checkpoint, then exceeded a12GiB virtual-memory cap on the second boundary. Symmetric-ordering reruns at both mesh sizes also completed and saved the mounting-ring fields, then failed JSON serialization of a NumPy int32 before the second boundary. All original exit1 states and tracebacks are retained. None is relabeled as a fully successful two-boundary run.

recover_ring_fields.py actually reopens the complete field checkpoints and independently recomputes the free-DOF residual, force/moment balance, work/energy equality, compliance matrix, reciprocity and eigenvalues. All checks pass. The two solver orderings on the same mesh agree to about2.65e-9 relative diagonal difference; the two meshes differ by2.41..3.04% in the four mean-face compliances, within the declared5% comparison target. This is not a proof of global FE error or stress convergence.

A SEPARATE rigid-root isolated rectangular post comparator is solved with quadratic displacements at two meshes for each of the two post widths. It is not the uncompleted whole-panel rigid-skin case. With the same normalized full-face load and nu=.3, complete-panel ring-clamped responses are about2.93..3.12 times the isolated-post responses. This conditional model comparison demonstrates why a rigid post-root estimate should not stand in for panel compliance; it predicts no real service-load deformation or rating.

field_producer_used.py preserves the exact source that produced the symmetric-ordering checkpoints. solve_panel_probe.py separately fixes JSON scalar conversion and defaults to --boundary rings for subsequent reproduction. The corrected output writer was not used to retroactively regenerate the reported full-panel fields. Use a new output directory for fresh runs. The original bottom-skin boundary remains uncompleted, not silently replaced with isolated geometry.

Reproduce in a new folder with the pinned optional packages and existing locked NumPy/SciPy, using the unchanged candidate manifest and STEP: mesh_panel_probe.py --manifest ... --output NEW_MESH --size 2 ; solve_panel_probe.py --mesh NEW_MESH/mesh.npz --output NEW_SOLVE --order 2 --boundary rings.
