# Reviewed scientific evidence archive

This separate transfer job retains exact, already reviewed engineering ZIPs in the repository's unpublished draft release `evidence/engineering-sprint-20261026`. The selected artifact ID, run, immutable source head, original ZIP size and SHA-256, manifest digest and exact member count are fixed before execution. All ZIP members, bytes, SHA-256 values and CRCs are verified before creating or reusing the draft. Every uploaded asset is downloaded in full again and compared to its original ZIP digest.

The first frozen selection contains N4b's complete numerical fields and correction histories, L2a's original 89-call study, and L3's original 70-call correlated study. It includes original scientific arrays/BREP files and explicitly identified engineering projections. The full raw runtime collections were not exported by these runs and are not recovered or made durable by this transfer. Unlisted members, symlinks, identity mismatches and incomplete manifests are rejected.

This archival operation uses only the repository-scoped Actions token, with read access to Actions and write access to contents for a draft release. Credentials are sent only to GitHub's API/upload hosts; redirected binary transfer URLs receive no authorization header. No token, signed URL, API author identity or full API response is written to the receipt. The job cannot publish a release, overwrite or delete an existing asset, change repository settings or create a product qualification. Existing assets are reused only after exact metadata and complete-byte readback checks. The owned draft identity is rechecked before each scientific asset transfer/reuse, before the index upload, and after the complete index readback; observed changes stop further work. Source-controlled failure gates are retained without raw HTTP exception details. Failed or partially completed transfers remain explicit in the receipt.

The workload performs no CAD, FE, solve or qualification calculation. It runs on a hosted Ubuntu 22.04 runner with a 20-minute workflow limit, a 1 GiB address-space limit, at most 20 selected ZIPs, at most 512 MiB per ZIP and 2 GiB total compressed input, and an ordinary filesystem reserve of 2 GiB. Original native numerical/geometric resource limits remain attached to their original runs. Eight small negative and positive controls check member/hash integrity, extra runtime rejection, symlink rejection, and redirect credential isolation. No live external write occurs in these controls.

A successful receipt establishes preservation and byte identity of the selected assets at the recorded time. It is not a new native execution, an independent geometry kernel, a physical test or a release decision. All candidate, fabrication and manufacturing flags remain false. This draft requires repository push access to view; it is not published to repository release followers.

Official API references: https://docs.github.com/en/rest/releases/releases and https://docs.github.com/en/rest/releases/assets.

## First actual transfer failure and media-type correction

Run 40276434886 reached source N4b and received HTTP 415 before any release or asset write. Its bounded original receipt is retained in ARCHIVE_FIRST_RUN_RECEIPT.json. The first binary helper incorrectly used the release-asset media type for the Actions artifact route. Official GitHub artifact download documentation specifies application/vnd.github+json; release binary readback uses application/octet-stream. An anonymous read-only control also observed octet-stream rejected with 415 while the documented JSON media type reached the access check. The followup selects the media type by an exact allowlisted route and checkpoints metadata, ZIP transfer and member verification separately. API version and all scientific bindings are unchanged. Ten integrity controls pass, including both route media types, unexpected-route rejection, dropped credentials on redirect and owned draft rechecks.

Documentation: https://docs.github.com/en/rest/actions/artifacts#download-an-artifact and https://docs.github.com/en/rest/releases/assets#get-a-release-asset .
