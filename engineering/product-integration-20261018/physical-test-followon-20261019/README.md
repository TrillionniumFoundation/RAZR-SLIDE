# 捕获随动件的分件装入与真实时序分析

本轮机械增量针对一个具体装配问题：原套筒有封底和缩口，内级有大于缩口的保持肩；两组闭槽的销头又大于槽宽。因此，把完整成品分别沿轴线推入，不能形成原 CAD 中已经嵌套好的状态。本目录给出保留原最终材料的分件顺序，并保留原轴向装入失败作为负控。

这不是已经加工、连接和开合过的样机。新底盖和环的真实材料、连接工艺、连接强度和加工余量仍为 `null`。程序通过只表示所声明的有限实体和装入路径通过几何检查，不能把接触着的 CAD 面当成已焊好、粘好或锁好的接头。

## 1. 对应原件与装配阻塞

几何来源是 [cam_coupling.py](../../../integration/cam_coupling.py)，SHA256 固定为 `4a3bf1d2b86d31fa8e3d60d3412e15548bf42287ed95d756798f3d88c6c4e631`。来源改变时，脚本直接拒绝复用旧尺寸。原脚本的 `cam_head_assembly_and_actual_threads_not_designed` 并未被本轮的局部分件研究改成整机通过。

| 原局部对象 | 母件缩口半径 / 子件保持肩半径 | 有限材料事实 | 需要解决的实际装配步骤 |
|---|---:|---|---|
| CROSSHEAD 内 TUBE 0 → TELESCOPE 1 | 1.05 / 1.15 mm | 子肩比喉口大 0.10 mm；底面有 0.10 mm 封底 | 保持肩从何处进入母件内部 |
| TELESCOPE 1 → TELESCOPE 2 | 0.65 / 0.75 mm | 同样有缩口、底肩和封底 | 先装内层，再封底，再进入外层 |
| TELESCOPE 2 → 最内芯 | 0.25 / 0.35 mm | 最内芯还有半径 0.65 mm 的 CAM 双头 | 芯、底肩与两个销头的装入先后 |
| CAM 闭槽 / 双头销 | 槽宽 0.85 mm / 头外径 1.30 mm | 0.80 mm 颈部能位于槽中，1.30 mm 头不能沿槽板法向穿过闭槽 | 先放槽板，再封最后一片保持头 |
| KEY 闭槽 / CROSSHEAD 下随动销 | 槽宽 0.85 mm / 头外径 1.30 mm | 同样存在闭槽和一体双头捕获 | KEY 槽片穿过裸颈后再装下保持环 |

[captured_follower_assembly.py](captured_follower_assembly.py) 检查八个原成品沿轴向装入的负控：三对套筒分别从上和下插入，以及 CAM 槽片从上、KEY 槽片从下套过完整双头。负控计算的是整个指定直线装入路径的实体并集与母件交叠。它没有推断压铸包覆、先放芯再成形、开口件装后缩口等所有其他制造路线都不可能。

## 2. 分件后的材料与最小特征

方案把每侧原五个局部材料对象分为十二个实体，增加七个分件。另导出两片真实尺寸的有限槽条作为装配环境，因此局部交付一共十四个单件 STEP。套筒 / CAM 局部总装包含十个分件和一片 CAM 槽条，共十一个独立实体。

| 新分件 | 每侧数量 | 名义尺寸与最小特征 | 连接或工艺仍需解决什么 |
|---|---:|---|---|
| 三个开底母套 | 3 | 主筒径向壁厚均为 0.20 mm；原顶唇轴向厚度 0.10 mm | 实际材料、薄壁成形 / 加工与尺寸公差 |
| TUBE 0 / 1 / 2 底盖 | 3 | 直径依次 2.40 / 1.60 / 0.80 mm；厚度均为 0.10 mm | 周向接缝、连接准备、热或胶层引起的尺寸变化 |
| 裸最内芯 | 1 | 细杆外径 0.40 mm；上端颈部外径 0.80 mm | 真实材料、接头与过渡圆角；不能从理想圆柱推算疲劳强度 |
| 芯底保持环 | 1 | 外径 0.70 mm、内径 0.40 mm、厚 0.20 mm；环径向宽 0.15 mm | 从最内母套开底处连接到细杆，随后再装底盖 |
| CAM 上 / 下保持环 | 2 | 外径 1.30 mm、内径 0.80 mm、厚 0.20 mm；环径向宽 0.25 mm | CAM 槽片在两环之间；最后一环的真实连接与整壳工具入口 |
| 去下环的 KEY 随动销 | 1 | 保留原上肩、颈部和与 CROSSHEAD 的关系 | 置回整机时它属于 CROSSHEAD，不随 KEY 的 Y 位移移动 |
| KEY 下保持环 | 1 | 外径 1.30 mm、内径 0.80 mm、厚 0.20 mm | 槽片就位后从下方连接；完整 KEY / 壳体的工具入口 |

各母套、最内芯和 KEY 随动销重组后，分别与原局部材料计算双向布尔差。目标是原材料 `A \ B = 0`、新材料 `B \ A = 0`，没有通过扩大槽、缩小头或删掉保持肩获取装入通过。程序还重做三个关节的 `0.10`、`2.90` mm 两个允许端点和 `0.09`、`2.91` mm 两个越界负控，共十二项止挡检查。

零材料差是数学重合面的结果。实际焊料、胶层、压配过盈、焊缝熔深和倒角尚未赋值；选定真实连接方式后必须把这些材料和变形写回 CAD，再重算避让。原 FE 结果也不会自动获得新分件接头的刚度或载荷证明。

## 3. 十二步局部装入顺序

| 步骤 | 先固定的对象 | 当前装入对象及方向 | 为什么此时能装入 |
|---:|---|---|---|
| 1 | 最内开底母套 TUBE 2 | 裸芯从 `+Z` 向下 | 保持肩和两个 CAM 头环尚未安装，只有细杆进入喉口 |
| 2 | TUBE 2 与裸芯 | 芯底肩从 `-Z` 向上 | 底盖未安装，底肩可穿过原内孔 |
| 3 | TUBE 2、裸芯与底肩 | 最内底盖从 `-Z` 向上 | 底盖下面仍无外层套筒，底面连接接缝可从下侧处理 |
| 4 | 中层开底母套 TUBE 1 | 已封好的最内子总成从 `-Z` 向上 | 两个 CAM 头环仍未安装，上端裸颈能穿过中层喉口 |
| 5 | TUBE 1 与最内子总成 | 中层底盖从 `-Z` 向上 | 在进入更大的 TUBE 0 之前封合中层底面 |
| 6 | 最外开底母套 TUBE 0 | 中层与内层子总成从 `-Z` 向上 | 中层主体能通过外层喉口，较大保持肩最终留在母件内部 |
| 7 | TUBE 0 与嵌套件 | 最外底盖从 `-Z` 向上 | 应在 CROSSHEAD 装入壳体之前完成底部连接 |
| 8 | 已嵌套的裸芯系统 | CAM 下环从 `+Z` 向下 | 上环未装，下环能沿裸颈到达下保持面 |
| 9 | 套筒系统与 CAM 下环 | 有限 CAM 槽片从 `+Z` 向下 | 裸上颈外径 0.80 mm 小于槽宽 0.85 mm |
| 10 | 套筒系统与 CAM 槽片 | CAM 上环从 `+Z` 向下 | 槽片已经位于上下保持面之间 |
| 11 | 去下环的 KEY 随动销 | 有限 KEY 槽片从 `-Z` 向上 | 先让槽片越过裸下颈，原上保持面仍保留 |
| 12 | KEY 槽片与随动销 | KEY 下环从 `-Z` 向上 | 形成原名义轴向捕获材料，接头强度仍需实物验证 |

第 1–10 步是套筒 / CAM 局部子总成，第 11–12 步是另一个 KEY 槽 / 随动销的局部界面。它们尚不是完整 94 件原产品机构的全装配顺序。程序检查的 CAM 槽条没有把整块 B 壳的其他材料省略后又声称整壳能装入；KEY 槽条也没有代替完整长臂、原 KEY、底板和相邻机构的装入验证。

圆筒、环和底盖都用有限轴向区间定义。单个区间沿 Z 平移时，完整扫掠恰为同一环截面在扩大后的 Z 区间上的挤出；多个区间取实体并集。因此正向与反向都覆盖完整声明路径，没有只取十几个离散姿态。报告逐步列出子总成成员、最终 Z 偏移和所有已装障碍物。

底盖的名义周向接缝半径依次是 `1.20 / 0.80 / 0.40 mm`。它们都在本层进入下一层前从底面处理，避免把必须连接的面先封进外层。此处定义了可达方向和连接边界，未选择或声称完成微焊、钎接、粘接等任何具体工艺。真正首件必须先取得加工方能实现的接头尺寸、变形范围和拉脱数据。

## 4. 置回同一整机的独立入口

[product_split_assembly.py](../../../integration/product_split_assembly.py) 是完整共同场景的独立分件入口；[verify_product_split_assembly.py](../../../integration/verify_product_split_assembly.py) 对其导出做独立读回。本轮保留原 `product_scene` 默认入口和原历史证据，新入口单独说明分件身份。

每侧拆出的 TUBE 0 底盖和 KEY 下环来自 `L/R_CROSSHEAD`；TUBE 1 / 2 底盖来自 `L/R_TELESCOPE_1/2`；芯底肩与两个 CAM 头环来自 `L/R_TELESCOPE_3`。每侧新增七件，预期常装机械件由 `94 → 108`，带原 OPEN 附件由 `101 → 115`。是否在完整 STOW、PREDOCK 和 OPEN 场景中保留总材料、得到这些实际实体数，以该入口的真实运行报告和 STEP 读回为准。

本目录预定的完整场景输出名为 `common-split-assembly.tar.gz` 和 `common-split-readback.json`。这些输出需实际执行并由交付索引登记；只存在本说明或源文件不表示它们已经通过。

## 5. 真实开合 / OLED / FPC 日志可以直接分析

[analyse_motion_log.py](analyse_motion_log.py) 读取一个实际采集 manifest 和原始 CSV，输出同一版本下的操作力、左右位移差、回程偏移、松手漂移、OLED 牵引与 FPC 阻值观测。没有现场数据时不生成测得力、完成循环数、材料或电气通过。

入口 schema 为 `razr-unpowered-motion-acquisition-v1`。manifest 使用与平台采集一致的 `specimen_id`、`recorded_at_utc`、`design_binding.git_commit` 和 `design_binding.files_sha256`；几何与接口文件都必须有精确 SHA256。`physical` 记录还执行本地 `git cat-file`，核验该 40 位身份确实是 Git commit，且每个被绑定文件在该 commit 中的原始字节与所填 SHA256 一致。仅工作区文件恰好匹配、但所写 commit 包含另一个版本时会拒绝。

原始 CSV、校准记录、校准原始附件、坐标系、阶段 / 手接触状态记录和时钟同步证据均用 `path + sha256` 绑定。文件需位于各自声明目录之内；路径逃逸、内容更改、缺附件或单位不符不会静默降级。Git 对象读取只读，不 fetch、不提交、不修改设备。

| CSV 字段 | 含义与来源要求 |
|---|---|
| `t_s` | 全日志严格递增的统一单调时钟，单位秒；保留时钟来源、同步依据与对齐误差 |
| `cycle`、`phase` | 明确样次和操作阶段；阶段与手状态有同步原始依据 |
| `hand_contact` | `0/1`；`HANDS_OFF_OPEN` 中不能同时标记手仍扶住 |
| `left_y_mm`、`right_y_mm` | 同一参考坐标内的两侧纵向位置，不能由单个中心点复制出两路 |
| `left_z_mm`、`right_z_mm` | 同一参考坐标内的两侧法向位置，区分就位和左右倾斜 |
| `operator_force_N` | 实际仪器记录的外部操作力，不当作内部 KEY 轴向 / 横向力 |
| 可选 `oled_tail_y_mm`、`oled_pull_force_N` | OLED 牵引端相对其所声明坐标的位移与拉力 |
| 可选 `oled_min_radius_mm`、`fpc_min_radius_mm` | 有对应几何识别方法和校准的材料弯区半径观测；缺测留空 |
| 可选 `fpc_c01_ohm` … `fpc_c26_ohm` | 逐通道、逐采样时刻阻值；缺数值留空，仪器超量程明确写 `OVER_RANGE` |

每个数值通道引用 `razr-linear-sensor-calibration-v1` 校准文件，记录仪器身份、输出单位、`gain`、`offset`、`absolute_error_bound`、有效原始范围和原始校准附件。处理公式是 `raw × gain + offset`。超出校准范围的读数拒绝分析；物理记录不接受零误差声明，也不接受 `synthetic_fixture` 校准冒充实测。

操作阶段完整保留锁闭基线、左右解锁、上滑、就位、两侧保持件安装、支撑安装、松手观察、支撑拆除、两侧保持件拆除、退出就位、下滑、左右复锁和最终锁闭观察。记录可以中途停止，实际观测的阶段序列会保留；`phase_label_complete_cycles` 只说明记录标签与声明操作表相符，没有自动把最终位置设成零或证明锁扣已经承载。

左右差的误差界采用两通道误差的保守相加。松手漂移从每段第一次实测位置算起，并保留全段最大偏移；采样间隙过大时拆开观察段，不跨缺数区间串成一次连续保持。FPC 阻值若有单独证据支持的阈值，区分“考虑误差仍超阈值”和“处于误差边界、结论不确定”；没有阈值时仍输出实际采样极值，判断字段为 `null`。

没有在采样时刻发现断续不能证明两个采样点之间没有更短的掉线。因此输出保留最大实际采样间隔、全部超限时间段、缺数与超量程事件，并固定 `absence_of_unsampled_dropout_proved: false`。相机画面、USB 软件日志、导通采集仪与力传感器若有不同时间源，应先有可追溯的同步和坐标转换，不能只把不同起点的时间列直接拼接。

真实 OLED 的总材料长、有效端夹长度、夹具实际占用长度、COF 禁弯区、完整厚度、FPC 刚柔过渡位置，以及夹持滑移 / 拉脱起始力属于具体样件和静态几何证据。它们应和原始照片、规格、尺寸文件一同进入平台与几何导入；时序分析不会用设计占位数字替代这些静态实测量。

## 6. 实测怎样进入结构研究

新的结构输入必须与真实部件和本轮分件接头相符。第一批应取得实际材料 / 模量依据、KEY 各段的实际截面、真正未受支撑的跨度、导向接触位置与间隙、端接连接刚度，以及能定位受力点和方向的载荷记录。当前名义 `0.25 × 0.30 mm` 截面与 `23.8 mm` CAD 延伸仍不能代替实物截面和自由跨度。

时序分析先给出真实外部操作力的采样包络、阶段和时间。它明确不把这个力直接施加到 KEY，也不为原 PR35 生成虚假的内力、力点或支承条件。若没有独立测得的 KEY 载荷或可核验的力传递模型，`actual_KEY_material`、`actual_KEY_unsupported_span_mm`、`actual_KEY_axial_and_lateral_load_N` 均为 `null`。

接下来能指导改形的实验是：在同一尺寸样件上测实际导向跨度和左右偏差；对明确材料与接头的薄件 / 保持环测试位移、松手保持或拉脱；把对应的载荷与边界传入新版结构模型。新分件总材料与旧件相同，并不保证新的接头刚度和连接强度相同。PR35 的旧缓存身份和全区域失败仍需按原规则独立处理，本目录不运行新 FE/QP 求解。

## 7. 执行入口与验证范围

在完整仓库和 CAD 运行环境中，选择新的输出目录：

```bash
python engineering/product-integration-20261018/physical-test-followon-20261019/captured_follower_assembly.py \
  --native-source integration/cam_coupling.py \
  --verify-native \
  --output /tmp/razr-captured-follower-NEW

python -m unittest discover \
  -s integration/product-study-tests \
  -p test_physical_followon.py -v
```

`--verify-native` 除了检查来源 hash，还运行原构造器，比较原套筒 / 芯 / CAM 实体，并核验两个局部原始材料确实包含在原 CROSSHEAD / KEY 中。独立 STEP 读回属于另一个入口，不把构造器自己返回的实体数当成独立读回结论。

本轮新增十一项产品测试：九项时序与身份检查、两项局部装配和源身份检查。合成采集数据只在测试临时目录内生成，明确标为 `synthetic_fixture`，测试结束删除。它们验证分析器会正确处理漂移、校准、采样缺口、FPC 不确定阈值和错误版本，不是实物循环结果。

取得真实采集文件后运行：

```bash
python engineering/product-integration-20261018/physical-test-followon-20261019/analyse_motion_log.py \
  --manifest /absolute/path/to/specimen/acquisition.json \
  --repository /absolute/path/to/RAZR-SLIDE \
  --output /absolute/path/to/specimen/motion-analysis-NEW.json
```

当前没有在本目录留存虚构的样件记录或已完成的物理循环。真实制造、受载保持、拉脱、OLED 运动、供电和 USB 连续性应由之后采集的原始证据回答。
