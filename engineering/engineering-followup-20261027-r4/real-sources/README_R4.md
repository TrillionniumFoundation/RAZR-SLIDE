# R4：精确型号来源与实物输入边界

本轮取得了可核对全字节身份的 Lenovo 手机服务页面，明确把 **XT2551-3** 对应到 **moto razr 60 Ultra**，并取得该型号的消费指南下载目录和一个可用于准备原机 USB 基线方法的官方来源。仍未取得受控维修手册、原理图、选定零件的完整叠层，或同一样件的新增实物原件。

控制结果为 `R4_SOURCE_EXECUTED_SUMMARY.json`。原 R3 的 V2 入库合同与 37 项既有合成控制均未修改，也没有将它们重跑成新的物理证据。

## 日期冲突与真实访问失败

| 文档声明 | 下载目录日期 | 详情日期 | 本轮判断 |
|---|---|---|---|
| 快速入门 | 2025.07.23 | 2025-04-25 | 两者保留，不能据此选定内部 revision |
| 合并用户指南 | 2025.08.22 | 2025-05-08 | 两者保留，不能据此选定内部 revision |

两个官方正文下载均重定向到 `file03.lenovomobile.com` 后返回 HTTP 503；对同一主机、同一文件的标准 HTTPS 重试也分别返回 503。另两次 L2 手册路径读取中，iFixit CDN 路径返回 HTML，接收至预定的 65,536 字节前缀上限；ReplaceBase 路径返回 HTTP 405。

因此，六次实际文档读取均没有得到完整 PDF 或 RAR。本轮没有 PDF 页码核验、正文全文散列、器件针序或叠层证明，也不据此断言源站文件不存在。没有登录、提供凭据、关闭 TLS 验证或绕过访问控制。见 `R4_DOCUMENT_BODY_READ_OBSERVATIONS.json`。

## 对原 228 项要求的实际作用

| 原要求类别 | 数量 | 本轮新增合格原件 |
|---|---:|---:|
| 同样件身份 | 10 | 0 |
| 七种零件角色的逐事实观察 | 77 | 0 |
| 十二个 OEM 接口的逐事实观察 | 120 | 0 |
| 选定 PN/revision 的供应商与工艺证据 | 21 | 0 |

前 207 项需要同一样件原件；另 21 项需要选定零件 revision 的供应商／工艺资料。官方型号网页不能替代照片标签、量测及不确定度、端子来源、实际原机功能、材料性能或动态弯曲限制。`R4_ORIGINAL_228_REQUIREMENT_COVERAGE.json` 逐项保留原要求与未绑定原因，是本轮来源覆盖记录，不是新建空入库模板。

`R4_G4_USB_PROTOCOL_SOURCE_CANDIDATE.json` 给出可供 G4 原机 USB 方法准备引用的来源链和概括步骤。它尚未冻结候选合同，没有实际文件传输，也没有确认 USB 版本、速率、终端针序、误差限或改造后电气资格；真实 G3 前置通过仍然缺失。

北美 XT2551-1/-2 维修资料对 XT2551-3 的适用性仍未建立。新取得的精确型号消费页面不能使旧北美工程文档自动适用。

## 当前真实接入状态

两轮有界的上传原件检索没有返回匹配项；这不是全局不存在证明。对原记录的唯一设备服务进行了本轮一次 3 秒上限的 TCP 观察，结果仍为连接拒绝；未向服务发送应用字节，未扫描其他主机或端口，未执行设备命令。当前环境没有 adb 可执行文件。记录格式沿用原 observer 的版本，其本轮时间、原程序 SHA 和前置观察身份都单独绑定于 `DEVICE_CONNECTIVITY_R4.json`。

新增实物测量、真实 G3/G4/G5 通过数均为 **0**；当前 FE、OEM 电气与叠层、候选、夹具和制造放行均保持 **false**。下一项实物进展仍需要当前同一样件的原件或可用的既有设备接入，以及适用 PN/revision 的受控工程资料。
